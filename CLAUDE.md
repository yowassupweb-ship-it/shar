# Шар — как здесь работать

Инструкции для агентов и людей, которые меняют этот репозиторий. Общий контракт MBOX (задачи, память, отчёты)
действует поверх них.

## Задачи и память — MBOX

- Проект в MBOX: **`shar-messenger`**. Начать — `get_agent_context(project="shar-messenger")`.
- Работа — только по задаче MBOX: найти существующую (`claim_task`) или создать. Параллельных списков в репозитории не вести.
- После заметного шага — `record_memory`: что изменено, файлы, коммит, почему. Закончили — `finish_task` (статус `review`,
  пока владелец не проверил в интерфейсе).
- Вопрос владельцу, решение, отчёт — через inbox MBOX.

## Порядок работы

1. **Понять и найти.** Прочитать код вокруг, повторить стиль: имена, комментарии по-русски о «почему», плотность.
2. **Сделать.** Маленькими законченными шагами. Новый маршрут API закрыт по умолчанию (`core/security.py`).
   Новая таблица — через `schema.register` с `IF NOT EXISTS`. Код, который её ждёт, должен работать и без неё
   (`store.table_ready`), потому что на проде схема догоняется отдельно.
3. **Проверить:**
   ```bash
   npm run typecheck && npm run lint
   cd server && .venv/bin/python -m pytest -q        # тесты на новое — рядом, в server/tests
   ```
   Интерфейс — глазами: `npm run dev` или `./scripts/dev-prod.ps1 -Electron` (на боевой базе!).
4. **Закоммитить** в `main` (или ветку для большого): одна тема — один коммит, сообщение по-русски о сути.
   В `origin` пушить только с разрешения владельца.
5. **Выпускать** только законченное и только по «да» владельца: [docs/RELEASE.md](docs/RELEASE.md).

## Выпуск — главное

- Прод = git: выкладывается чистый запушенный `main` (`scripts/deploy-server.ps1`, сначала без `-Execute`).
- Одна сборка везде: тот же `dist/` идёт на сайт и в Shar OS (`scripts/publish-electron.ps1` сверяет `index-*.js`).
  Интерфейс в Shar OS встроенный. Грузить его с сервера не предлагать.
- Схема на проде — отдельным шагом (`-Schema`, `python -m app.migrate --schema-only`), автомиграций нет.
- Shar OS: версия выше опубликованной, `latest.yml` — последним.
- Бэкап перед любым изменением на сервере: `/root/backups`.

## Нельзя

- Класть секреты в git или MBOX: пароль SSH лежит в файле вне репозитория, настройки прода — в `/opt/shar-next/api.prod.env`.
- Включать фоновые задачи у второго экземпляра на боевой базе: их выполняет старый бэкенд, будут дубли.
- Менять прод «руками» мимо скриптов, если скрипт это умеет; если не умеет — описать шаг в `docs/RELEASE.md`.

## Где что

- `src/features/<раздел>` — интерфейс, `src/shared` — общее; `server/app/modules/<раздел>` — API.
- `desktop/electron/main.cjs` — Shar OS: окно, трей, уведомления, обновления.
- `docs/RELEASE.md` — прод и выпуск; `docs/MCP.md` — агенты по MCP; `docs/INTEGRATION_API.md` — внешний API.
- Рядом лежит `../shar-sync` — второй рабочий каталог (git worktree, ветка `server-sync`) с локальной базой
  `.localdev` (PostgreSQL `:5433`, роль `shar`). Он подходит для тестов: `SHAR_TEST_DB_PORT=5433 SHAR_TEST_DB_USER=shar`.
