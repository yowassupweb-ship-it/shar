# MCP «Офиса»

ИИ-агент (Claude, Cursor и другие клиенты MCP) работает с заметками, документами, таблицами и папками Шара от имени
человека и **только там, куда тот его пустил**. Ключ не даёт агенту больше, чем есть у самого человека, и обычно даёт
меньше.

## Подключение

1. В Шаре: **Настройки → MCP → Новый ключ**. Выбрать доступ (см. ниже) и срок. Ключ показывается один раз, на сервере
   хранится только его SHA-256.
2. В агенте добавить сервер `https://vokrug-sveta.shar-os.ru/api/mcp` с заголовком `Authorization: Bearer <ключ>`.

Claude Code:

```bash
claude mcp add --transport http shar https://vokrug-sveta.shar-os.ru/api/mcp --header "Authorization: Bearer shar_mcp_..."
```

Cursor и `.mcp.json`:

```json
{ "mcpServers": { "shar": { "type": "http", "url": "https://vokrug-sveta.shar-os.ru/api/mcp", "headers": { "Authorization": "Bearer shar_mcp_..." } } } }
```

## Доступ ключа

| Настройка | Варианты |
| --- | --- |
| Что можно | **Только читать** · **Читать и править** (текст, ячейки, названия) · **Править и создавать** (новые материалы и папки, раскладка) |
| Какие материалы | заметки, документы, таблицы, презентации (презентации — только чтение) |
| Где | весь «Офис» или **только выбранные папки** (вложенные открыты вместе с родительской; новое — только внутри них) |
| Чужие материалы | открыты ли агенту материалы, которыми с человеком поделились коллеги |
| Срок | без срока, 30 дней, 90 дней, год |

Доступ можно поменять в любой момент кнопкой «Доступ» у ключа. Ключ остаётся тем же, агенту ничего перенастраивать не
нужно, новое действует со следующего вызова. Отзыв тоже действует сразу. У отключённого сотрудника ключи не работают.

Чего нет за пределами доступа, для агента не существует: он не видит такие материалы в списках и не может прочитать их
по id (ответ тот же, что на несуществующий материал). Инструменты выше уровня ключа агенту даже не показываются.

## Безопасность правок

- **Версия перед каждой правкой** с пометкой «До правки агента «<ключ>»»: прежнее возвращается из истории версий материала.
- **Правка не затирает чужую.** Если материал изменили после того, как агент его прочитал, правка не пройдёт: ответ содержит
  `error.code = stale_version`, после которого нужно перечитать материал. Другие машинные коды: `text_not_found`,
  `text_not_unique`, `not_found`, `permission_denied`, `permission_required`.
- **Предпросмотр без записи.** У `edit_note`, `update_note`, `edit_document`, `update_document`, `update_table` и
  `restore_item_version` параметр `dry_run: true` возвращает unified `diff`, `baseUpdatedAt` и `changed`, ничего не меняет.
  В осторожном режиме Ядра предпросмотр не требует разрешения на запись.
- **Подтверждение записи.** Успешная правка содержимого возвращает фактический новый `updatedAt`.
- **Точечные правки**: `edit_note` и `edit_document` меняют только указанный кусок. В документе оформление (жирный, ссылки,
  заголовки, таблицы, картинки) остаётся на месте.
- **Журнал**: у каждого ключа в настройках видно, что агент делал: что прочитал, что поправил или создал, что ему не
  удалось. Хранятся последние 500 записей; чтение списков в журнал не пишется.
- Удаления и выдачи доступа у агента нет совсем.
- Лимит: 120 вызовов в минуту на ключ.

## Работа в реальном времени

Правка агента — обычная правка материала: через доли секунды её видят все, у кого материал открыт, включая самого
владельца ключа. Проверено сквозным прогоном через официальный MCP SDK (27.10.2026): правки 11–20 мс, события доходят
до окон владельца и коллеги, содержимое у них обновляется.

- **Заметки:** правка агента вливается в открытую заметку на месте, без перезагрузки и прыжка курсора. Если человек в
  этот момент печатает, его текст и правка агента сливаются.
- **Документы и таблицы:** открытый редактор перечитывается целиком. Если человек как раз правит тот же материал, при
  его сохранении появится выбор «оставить мою / взять чужую», молча ничего не затирается.
- Агент правит всегда свежую версию: точечные правки (`edit_note`, `edit_document`, `update_table`) читают материал в
  момент вызова, поэтому правки человека, сделанные раньше, сохраняются.

## Инструменты

| Инструмент | Уровень | Что делает |
| --- | --- | --- |
| `list_items` | читать | материалы: вид, поиск по названию и тексту, папка, постранично |
| `list_folders` | читать | открытые ключу папки с путём и числом материалов |
| `read_item` | читать | содержимое; для таблицы — `sheet`, `range` (`A1:B20`), `offset`, `max_rows`, `max_cols`; ответ содержит `totalRows`, `totalColumns`, `hasMore`, `nextRange` и формулы; для заметки и документа — страница до 40 000 знаков, `outline` (заголовки с `offset`) и `section` (прочитать один раздел); таблицы документа читаются таблицами Markdown. `list_items` с `query` у найденных заметок и документов отдаёт `matches` (фрагмент, раздел, `offset`) |
| `resolve_item` | читать | открыть внутреннюю или публичную ссылку на материал с обычной проверкой прав |
| `item_versions`, `diff_item` | читать | история версий и diff с выбранной или последней сохранённой версией |
| `capabilities` | читать | права ключа и на конкретный материал, серверное время, компактный список доступных инструментов |
| `tool_search` | читать | компактный поиск инструментов; схемы параметров — с `include_schema: true` |
| `edit_note` | править | заменить кусок заметки; поддерживает `dry_run` |
| `update_note` | править | переписать заметку или дописать в конец; поддерживает `dry_run` |
| `edit_document` | править | заменить кусок документа внутри абзаца с сохранением оформления; поддерживает `dry_run` |
| `update_document` | править | `append` — в конец, `insert` — после абзаца с `after_text`, `replace` — пересобрать; по заголовку (`heading`, точный текст не нужен): `replace_section`, `delete_section`, `append_to_section`, `insert_after_heading`, `insert_before_heading` — раздел с таблицей или картинкой целиком не заменяется; поддерживает `dry_run` |
| `batch` | читать | до 20 вызовов `{tool, arguments}` одним запросом (правки в разных материалах); права и разрешения — у каждого вызова отдельно, остановка на первой ошибке; `dry_run` — предпросмотр всех правок |
| `update_table` | править | ячейки (`B2` латиницей), формулы, ссылки, строки; `operations` меняет несколько листов одной записью; поддерживает `dry_run` |
| `restore_item_version` | править | восстановить версию с `confirm: true`; текущее состояние тоже остаётся в истории |
| `list_comments` | читать | комментарии документа или таблицы ветками: привязка (цитата или ячейка), автор, ответы, решено ли |
| `add_comment` | править | новая ветка (`quote` у документа, `cell` и `sheet` у таблицы) или ответ (`thread_id`); содержимое не меняется |
| `resolve_comment` | править | закрыть ветку («решено») или открыть снова |
| `rename_item` | править | название |
| `create_note`, `create_document`, `create_table` | создавать | новый материал (в выбранной папке, если ключ ограничен папками) |
| `move_item`, `create_folder` | создавать | раскладка по папкам |
| `delete_item` | создавать | удалить свой материал в корзину «Офиса» (30 дней, вернуть может человек); только с `confirm: true` |

## Ссылки

- В `list_items` и `read_item` у материала есть `url` — внутренний адрес `/office?kind=<note|document|table|presentation>&id=<id>`.
  Домена в нём нет: он у Шара меняется, а приложение открывает такую ссылку само (и браузер, и Shar OS — внутри окна).
- `/d/<токен>`, `/t/<токен>` и подобные — публичные ссылки по токену, их выдаёт человек в «Поделиться». Агент передаёт такую
  ссылку в `resolve_item`: токен разрешается в id, но затем заново проверяются права человека и ключа — публичная ссылка не
  открывает агенту чужой закрытый материал.
- Ссылка в ячейке таблицы: `{ref: "F11", value: "текст", link: "/office?kind=document&id=94"}`; то же — `value: {text, hyperlink}`
  и формула `=HYPERLINK("адрес"; "текст")`. Запись `value` заменяет и прежнюю ссылку ячейки (раньше текст менялся, а ссылка
  оставалась старой); `value: null` очищает и текст, и ссылку. `read_item` у таблицы отдаёт `links: {ячейка: адрес}`.

## События и запуски агента по времени

`changes_list(since, cursor?, limit?)` возвращает изменения доступных материалов «Офиса», комментарии и входящие
уведомления о задачах и календаре с указанного
ISO-времени с часовым поясом. `nextCursor` продолжает ленту; для деталей правки есть `item_versions` и `diff_item`.
Скрытые от ключа материалы в ответ не попадают. Для заметки `read_item(tab=...)` читает одну вкладку, а
`edit_note(tab=...)` меняет только её текст, сохраняя служебные маркеры остальных вкладок. Точечные правки сначала
ищут точную строку, затем допускают визуально одинаковые пробелы, тире и кавычки; несколько совпадений требуют уточнения.

Ключам запусков «Ядра» доступны также `events_list`, `agent_schedule`, `agent_schedules` и `agent_schedule_cancel`.
`events_list` читает только входящие уведомления владельца ключа и не меняет их прочитанность. Планировщик поддерживает
разовый (`frequency=once`, `at`), ежедневный (`daily`, `time`) и еженедельный (`weekly`, `time`, `weekdays`: 0 — понедельник)
запуск. В назначенное время сервер создаёт обычное сообщение в чате «Ядра» и обычную задачу `core_jobs`: дальше работает
та же нода и тот же MCP-ключ на один запуск. Расписания и отметки напоминаний хранятся в Postgres, повторная обработка
одного срока не создаёт дубль. Время без указанной зоны и ежедневное/еженедельное `time` трактуются как МСК независимо от зоны сервера.
Отмена требует `confirm: true` и не останавливает уже созданный запуск. `request_permission(tools=[...], summary=...)`
может запросить одно согласие на конкретный план из нескольких инструментов; оно действует 15 минут только для перечисленных имён.

Для GPT нода версии 1.2.4 включает встроенный `image_gen`; полученная картинка сохраняется в «Файлы → Агенты» и
прикрепляется к ответу без использования квоты Gemini. Остальные агенты (Claude, Kimi, Gemini и внешние по MCP) рисуют своим средством и отдают готовую картинку инструментом
`image_attach` (base64 или вложение Шара `/api/uploads/…`): она попадает в «Файлы → Агенты» и в чат. MCP `image_generate`
через Gemini — только запасной путь, ключ Gemini для картинок не обязателен.

### Файлы: правка на месте

`file_read` отдаёт `rights` (owner/edit/view), `canEdit`, `editable`, `editWith`, кодировку и переносы строк. `file_edit` правит
текст и код (`replace`, `lines`, `append`; кодировка и CRLF сохраняются), docx/pptx (`replace` внутри абзаца без потери оформления;
docx — ещё `append`) и xlsx (`cells`, `append_rows`; диаграммы и картинки книги openpyxl не сохраняет). Править можно свой файл и
файл, где человеку дано право редактирования (в списке файла или любой папки над ним). Каждая замена оставляет прежние байты
версией (последние 10 в `metadata.versions`): `file_versions`, `file_restore_version`. Версии, созданные правками агентов,
стираются вместе с файлом; исходная загрузка не трогается — она может быть вложением чата.

## Устройство

- `server/app/modules/mcp/keys.py` — ключи и их доступ (`/api/mcp/keys`, по сессии), журнал, проверка ключа
  (`context_for_token`). Таблицы `mcp_keys`, `mcp_key_log`;
- `server/app/modules/mcp/router.py` — `POST /api/mcp`: JSON-RPC 2.0 по Streamable HTTP (MCP 2025-06-18), ответ обычным
  JSON, без сессий (`GET` — 405). Маршрут открыт в `core/security.PUBLIC_METHODS`, личность и доступ — по ключу;
- `server/app/modules/mcp/tools.py` — `Access`, доступ ключа на время вызова (папки раскрыты во вложенные), и
  инструменты. Инструменты зовут обработчики `workspace/router.py` и `workspace/folders.py` от имени человека, так что права,
  версии и живые события те же, что у интерфейса;
- `server/app/modules/mcp/docformat.py` — Markdown ↔ снимок Univer (перенос клиентского `lib/docSnapshot.ts`) и замена
  текста со сдвигом всей разметки;
- `src/features/settings/sections/McpSection.tsx`, `McpKeySheet.tsx` — раздел настроек;
- тесты — `server/tests/test_mcp.py`.

Таблицы MCP появляются на проде шагом выпуска (`deploy-server.ps1 -Schema`). До этого раздел настроек отвечает «MCP ещё не
включён на сервере».
